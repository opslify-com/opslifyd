# Manual test — credential-blind GitLab (LIVE, rootful) — validated procedure

This is the **verified-on-a-real-host** procedure (2026-08-22). It supersedes the
generic steps in `F5.7-credential-blind-gitlab.md` with the exact setup that works,
including the two fixes the live run required.

## Hard requirements (learned live)
- **Rootful podman** (`sudo`). The credential-blind proxy binds the bridge GATEWAY,
  which must live in the daemon's own network namespace — true for rootful podman,
  NOT for rootless (pasta/slirp4netns has no bindable gateway). nftables egress
  enforcement also needs root. Rootless fails **closed** (safe), it just can't inject.
- **Binaries built from the branch with the two F5.8 fixes** (`sandbox_network` +
  `host_input` hole). Until merged, use the freshly-built binaries.
- An **`opslify0` bridge network** so the sandbox has a routable gateway.
- A base image with **`curl` + `ca-certificates`**.
- A real **GitLab PAT** with `read_api` (or `api`) scope.

## Paths used below
Adjust to taste. `OPT` is a working dir the daemon can read.
```bash
export BIN=<dir with the freshly-built opslify + opslifyd>   # e.g. daemon build output
export OPT=/etc/opslify                                       # or any dir you control
```

## 1. One-time host setup
```bash
# a) bridge network whose interface is opslify0 (gives sandboxes a routable gateway)
sudo podman network create --interface-name opslify0 opslify-net

# b) a base image with curl + CA certs
printf 'FROM docker.io/library/alpine:3.20\nRUN apk add --no-cache curl ca-certificates\n' > /tmp/opslify.Containerfile
sudo podman build -t opslify-base:latest -f /tmp/opslify.Containerfile /tmp
```

## 2. Config (`$OPT/config.yaml`)
The daemon is authoritative — a workspace can never add/widen `egress_inject`.
```yaml
image: localhost/opslify-base:latest
session_ttl: 30m
warm_pool_size: 0
egress_allowlist: [gitlab.com]          # daemon's own egress leg to gitlab
workspace_dir: /var/lib/opslify/workspaces
sandbox_network: opslify-net            # <-- FIX 1: sandbox on the opslify0 bridge
tier: local-docker
identity_key: /etc/opslify/identity.key
vault:
  path: /var/lib/opslify/vault.db
  key_file: /etc/opslify/vault.key
policy_file: /etc/opslify/policy.yaml
trace:
  dir: /var/lib/opslify/trace
egress_inject:
  - host: gitlab.com
    secret_ref: gitlab-token
    header_name: PRIVATE-TOKEN
    header_format: "%s"                 # PRIVATE-TOKEN: <raw>. Use "Bearer %s" for Authorization APIs.
```

## 3. Policy (`$OPT/policy.yaml`) — must BOTH grant the cred AND egress-allow the host
The egress-inject rule only lights up when the resolved policy has both.
```yaml
egress:
  domains: [gitlab.com]
creds:
  - name: gitlab-token
    provider: gitlab
```

## 4. Generate keys (one-time)
```bash
sudo $BIN/opslify init --config $OPT/config.yaml \
  --identity-key $OPT/identity.key --vault-key-file $OPT/vault.key --yes
# ^ prints the vault master key ONCE — save it. (It also tries to build a signed
#   toolchain; if nix/cosign are absent it just warns — fine, we use --dev-skip-verify.)
```

## 5. Start the daemon (rootful) — keep this terminal open
```bash
sudo $BIN/opslifyd --config $OPT/config.yaml \
  --socket /run/opslifyd.sock --socket-group opslify \
  --dev-skip-verify
```
Wait for these lines:
- `egress: default-deny enforcement active (nftables)`
- `F5.7 credential-blind egress inject active rules=1`
- `listening ... /run/opslifyd.sock`

## 6. Seed the REAL token (never in config, never in the sandbox)
In a second terminal (value comes from stdin — never an argument):
```bash
sudo $BIN/opslify secrets add gitlab-token --provider gitlab --socket /run/opslifyd.sock
# paste your PAT, then Ctrl-D
sudo $BIN/opslify secrets ls --socket /run/opslifyd.sock   # shows the NAME only, never the value
```

## 7. Prove it — credential-blind API call
```bash
# The granted call succeeds WITH the injected token (agent never provided it):
sudo $BIN/opslify run --socket /run/opslifyd.sock \
  curl -sS "https://gitlab.com/api/v4/projects?membership=true&per_page=3"
#   => a JSON array of YOUR projects (authenticated)
```

Then prove the token is NOWHERE in the sandbox. Create a kept session and inspect it
(**note: `--socket` must come BEFORE the session id for `session exec`**):
```bash
SID=$(sudo $BIN/opslify run --socket /run/opslifyd.sock --keep true | grep -oE '[0-9a-f]{32}' | head -1)

# a) no token in the sandbox env (only HTTPS_PROXY + CA path):
sudo $BIN/opslify session exec --socket /run/opslifyd.sock $SID env | grep -i token   # => nothing

# b) the CA file is a certificate, not a secret:
sudo $BIN/opslify session exec --socket /run/opslifyd.sock $SID head -1 /workspace/.opslify-ca.pem
#   => -----BEGIN CERTIFICATE-----

# c) the authenticated call works from inside the session, blind:
sudo $BIN/opslify session exec --socket /run/opslifyd.sock $SID \
  curl -sS "https://gitlab.com/api/v4/user" | head -c 200
#   => your GitLab user JSON — authenticated, yet no token in the sandbox
```
On the wire to gitlab.com the `PRIVATE-TOKEN` header is present — added by the daemon
at the boundary. Inside the sandbox: no token in env, CA file, or `/proc`.

## 8. Fail-closed spot check
```bash
# A host with NO egress_inject rule stays under default-deny (no proxy, no creds):
sudo $BIN/opslify run --socket /run/opslifyd.sock curl -sS -m 8 https://example.com
#   => times out / refused (default-deny egress; no injected route)
```

## Cleanup
```bash
sudo $BIN/opslify session ls --socket /run/opslifyd.sock          # see live sessions
sudo $BIN/opslify session kill --socket /run/opslifyd.sock <id>   # ends + tears down its nft table
# stop the daemon with Ctrl-C (graceful teardown removes per-session nft tables)
```

## Gotchas (all hit + solved during live validation)
- **Empty curl output / connection timeout** = the sandbox can't reach the proxy.
  Confirm you're on the fixed binaries (`sandbox_network` + `host_input` hole) and that
  `sandbox_network: opslify-net` is set. Check the session's nft:
  `sudo nft list ruleset | grep -A14 host_input` — you should see
  `ip daddr <gw> tcp dport { <port> } accept` before the `drop`.
- **`session not found`** = you put `--socket` AFTER the id. It must come BEFORE.
- **Leaked nft tables** after `kill -9` of the daemon (bypasses teardown): stale
  `host_input` chains at the same hook will drop new sessions' traffic. Flush them:
  `sudo nft list tables | grep opslify_sess | while read _ f t; do sudo nft delete table $f $t; done`
- **Rootless** = `no reachable bridge gateway ... fail-closed` in the log. Expected; use rootful.
- **Redaction**: a high-entropy PAT is scrubbed from captured output by F3.3; a low-entropy
  dummy string may not be — don't be alarmed if a *dummy* token shows in a trace echo.
