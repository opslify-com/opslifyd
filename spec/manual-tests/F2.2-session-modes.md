## What F2.2 does (what you're verifying)
- **`scratch`** (default): per-session `/workspace`, discarded on end.
- **`workspace`** (`--mode workspace --name <n>`): a **stable per-name host dir** (`<workspace_dir>/ws-<name>`) mounted at `/workspace`, **kept across sessions** and **re-mounted on resume** — so installed deps / cloned repos persist, including across a daemon restart. A rootfs snapshot (`opslify/ws-<name>:<n>`) is committed on clean end and used as the resume base image (secondary; retention-capped, default keep 3).
- **Security invariant:** a *resumed* workspace session still gets the **full hard-spec** (`--cap-drop=ALL`, `--userns=auto`, `--read-only`, `--pid=private`, seccomp) — only the FS carries over.

## Design note (why host-dir, not just `podman commit`)
With the always-on `--read-only` rootfs, the agent's only writable path is the `/workspace` **bind mount**, and `podman commit` does **not** capture bind mounts. So the **primary** persistence is the host directory; the rootfs snapshot is a secondary/future-proofing layer.

## Level 2 — persistence mechanism on real podman (VERIFIED 2026-08)
Runs anywhere with Docker. This is exactly what the daemon does (read-only rootfs + a bind-mounted per-name `/workspace`), minus the daemon:
```bash
docker run --rm --privileged --user 0 quay.io/podman/stable bash -c '
  WS=/tmp/ws-proj; mkdir -p "$WS"
  # session 1: read-only rootfs; agent writes to /workspace
  podman run --rm --read-only --cap-drop=ALL -v "$WS":/workspace:rw docker.io/library/alpine:3.20 \
    sh -c "echo installed-deps > /workspace/deps.txt; (touch /nope 2>/dev/null && echo BAD-ROOTFS-WRITABLE) || echo rootfs=READONLY-OK"
  # session 2: NEW container, SAME per-name dir -> state persists
  podman run --rm --read-only --cap-drop=ALL -v "$WS":/workspace:rw docker.io/library/alpine:3.20 \
    sh -c "printf persisted=; cat /workspace/deps.txt"
'
```
Expected:
```
rootfs=READONLY-OK          # read-only rootfs: writes only land in /workspace
persisted=installed-deps    # a fresh container sees the prior session's state
```

## Level 3 — full daemon + CLI, end-to-end (real Linux host)
Best on a bare Linux host with `podman`, `runsc`, and root. (On nested Docker the gVisor cgroup/runtime registration is finicky — the escape-suite Dagger harness handles that; a real box is the clean path. Use `tier: local-docker` (runc) to exercise everything F2.2-specific without gVisor.)

```bash
# build
cd daemon
go build -o /usr/local/bin/opslifyd ./cmd/opslifyd
go build -o /usr/local/bin/opslify  ./cmd/opslify

# minimal dev config
sudo mkdir -p /etc/opslify /var/lib/opslify/workspaces
cat | sudo tee /etc/opslify/config.yaml <<'YAML'
image: docker.io/library/alpine:3.20     # base rootfs for dev
tier: local-hardened                      # gVisor; set local-docker to test on runc
session_ttl: 30m
workspace_dir: /var/lib/opslify/workspaces
warm_pool_size: 0
YAML

# run the daemon (dev): --insecure-no-egress skips nft default-deny
sudo opslifyd --insecure-no-egress &

# --- the F2.2 test ---
# 1) create a workspace, write into /workspace
opslify run --mode workspace --name proj -- sh -c 'echo "deps v1" > /workspace/state.txt; uname -r'
# 2) resume the SAME workspace -> state persists
opslify run --mode workspace --name proj -- cat /workspace/state.txt      # => deps v1
# 3) confirm scratch does NOT persist
opslify run -- sh -c 'echo ephemeral > /workspace/x.txt'
opslify run -- sh -c 'ls /workspace'                                      # x.txt absent
# 4) list + remove
opslify ws ls                                                             # proj listed, snapshots >=1
opslify ws rm proj
opslify ws ls                                                             # proj gone

# restart persistence: stop the daemon (SIGTERM), start it again, then:
opslify run --mode workspace --name proj2 -- sh -c 'echo keep > /workspace/k.txt'
# ...restart daemon...
opslify run --mode workspace --name proj2 -- cat /workspace/k.txt         # => keep
```

### Caveats
- **verify-before-serve (F1.1)** fails closed unless `config.yaml` has a `toolchain_digest` from `opslify init` (needs nix + cosign). For a pure F2.2 test this is orthogonal — if it blocks you, ask for the `--dev-skip-verify` dev flag (not yet added) or run `opslify init` first.
- **`local-hardened`** needs `runsc` installed + registered as a podman runtime (`/etc/containers/containers.conf`: `[engine.runtimes]\nrunsc = ["/usr/local/bin/runsc","--ignore-cgroups"]`, and podman with `--cgroup-manager=cgroupfs`). `local-docker` (runc) avoids all of that.
- The MCP surface takes the same params: `opslify_session_create({mode:"workspace", name:"proj"})` then `opslify_exec` / `opslify_upload` / `opslify_download` against `/workspace`.

## What to look for (pass criteria)
- [ ] Workspace state written to `/workspace` is present on the **next** `--mode workspace --name <same>` run.
- [ ] Scratch sessions do **not** persist `/workspace`.
- [ ] State survives a **daemon restart** (stop → start → resume).
- [ ] `opslify ws ls` shows the workspace + snapshot count; `ws rm` deletes it (record + snapshot images + host dir); `ws rm` of an in-use workspace is refused.
- [ ] Read-only rootfs holds: writes outside `/workspace` fail.
- [ ] (gVisor tier) `uname -r` inside shows a gVisor kernel (e.g. `4.19.0-gvisor`), not the host.
