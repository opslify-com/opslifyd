# F5.9 — Credential-blind reachability on a real host (bridge network + host_input hole)

**Phase:** P5 · **Status:** in-progress · **Owner:** Builder (Go) · **Depends on:** F5.8 · **Blocks:**

## Goal
Close the two integration gaps a live-host run of the F5.7/F5.8 credential-blind egress
path exposed, so the injection actually completes end-to-end (not just unit-proven):
(1) the sandbox must attach to a bridge network that HAS a routable gateway, and (2)
the F1.4 default-deny `host_input` chain must admit the sandbox to the gateway-bound
credential-blind listener ports — otherwise the proxy is bound but the sandbox→proxy
SYN is dropped and every granted call times out.

## Why these were invisible to unit tests
Unit tests use fakes (no real podman/nft). The two enforcement halves — nftables
default-deny (needs root) and a gateway-bound proxy (needs a bridge gateway in the
daemon's netns) — had never run together live: rootless podman has no bindable
gateway, and the `--insecure-no-egress` smoke path programs no `host_input` chain. So
the collision (host_input dropping the sandbox→proxy hop) only appears on a rootful
host with enforcement ON. This feature is the "verified on a live host" follow-up F5.8
explicitly deferred.

## Scope
**In:**
- **`sandbox_network` config** (`ManagerConfig.SandboxNetwork` → `SessionSpec.Network`
  → `podman create --network`): attach sandboxes to an operator-provisioned bridge
  network whose interface is `opslify0`, giving each container a routable gateway the
  daemon can bind. Empty => engine default (unchanged legacy behavior).
- **`host_input` gateway-port hole**: `egress.SessionNet` gains `GatewayIP` +
  `LocalTCPPorts`; `buildApplyScript` emits, in the `host_input` chain ABOVE the
  terminal drop and BELOW the port-53 drop, `ip[6] daddr <gateway> tcp dport { ports }
  accept` — scoped to the gateway daddr AND (via the existing saddr line) this
  sandbox. Opens ONLY the bound credential-blind listener ports (F5.7 egress proxy,
  F5.1 creds endpoint, F7.5 registry proxy) on ONLY the gateway.
- **Manager re-program**: after the credential-blind listeners bind (their ports are
  known only then), `allowBlindPathPorts` collects the bound ports and re-applies
  `SetupSession` with the gateway + ports. It is a no-op unless the gateway path is
  live (`sn.ok`) and at least one listener bound — so a fail-closed/inactive blind
  path never widens `host_input`.

**Out:**
- Auto-provisioning the `opslify0` network (operator runs `podman network create
  --interface-name opslify0 …`; documented in the manual test) — the daemon consumes
  it, it does not create host networks.
- Rootless credential-blind egress (the gateway lives in the rootless netns, not the
  daemon's — documented as rootful-only; rootless still fails closed, never leaks).
- Changing the DNS-pinning / default-deny posture (port 53 stays dropped; the hole
  can never include 53).

## Acceptance criteria (testable)
- [ ] `SessionSpec.Network` set => `podman create` includes `--network <name>`; empty => no `--network` (legacy default). (runtime unit test)
- [ ] `host_input` emits `ip daddr <gw> tcp dport { <ports> } accept` above the terminal drop and below the port-53 drop, scoped to the gateway; the forward (egress) chain is unaffected. (ruleset unit test)
- [ ] No ports, or an unparseable/empty gateway => NO hole (host_input stays fully default-deny); port 53 is excluded from the hole even if passed. (ruleset unit test — fail-closed)
- [ ] After the blind listeners bind, the manager re-programs egress with the gateway + collected ports; with no reachable gateway (`sn.ok=false`) or no bound listener it does NOT re-program. (manager unit test — fail-closed)
- [ ] **(Integration, live rootful host):** with `sandbox_network` set, a granted `curl` from inside the sandbox reaches the upstream with the daemon-injected header, while the sandbox env/CA/trace carry no token; a non-injected host stays default-denied. (manual test `F5.7-credential-blind-gitlab-LIVE.md`)

## QA checklist
- [ ] The `host_input` hole is tightly scoped: daddr==gateway AND saddr==sandbox AND only the specific bound TCP ports; it never admits port 53 and never appears in the forward chain (a broad host-local hole would be BLOCKING).
- [ ] Fail-closed: no gateway / no bound listener / bad gateway => no hole, no reprogram; the blind path being unavailable never widens egress.
- [ ] Per-session teardown still deletes the whole table (hole vanishes with the session); no rule leak.
- [ ] `sandbox_network` empty preserves prior behavior; a set value only adds `--network`.
- [ ] No regression to F1.4 default-deny egress, F5.7/F5.8, F7.5.

## Security considerations
- **The hole is the narrowest possible.** It exists solely so the sandbox can reach the
  daemon's own credential-injecting listeners on the bridge gateway. Scoping to
  daddr==gateway + saddr==sandbox + exactly the bound ports means it can never reach
  another host-local service, another sandbox, or reopen the DNS/exfil channel (port
  53 is excluded and its drop sits above the hole).
- **Fail-closed is preserved end-to-end.** If the gateway is not reachable or no
  listener bound, no hole is opened and no credential is injected — the credential-blind
  path is simply unavailable, never a raw-secret or open-egress fallback.
- **Rootful is required and documented.** The gateway must live in the daemon's network
  namespace; rootless remains fail-closed (no bind, no injection), never a downgrade.
