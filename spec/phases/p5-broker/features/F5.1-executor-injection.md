# F5.1 — Executor-side credential injection (primary credential-blind model)

**Phase:** P5 · **Status:** in-progress · **Owner:** Builder (Go) · **Depends on:** F5.6 · **Blocks:** F5.2, F5.3

## Goal
The primary **credential-blind** model: the daemon (executor, on the trusted side) resolves a policy-granted secret and injects a **scoped, short-lived** credential into the spawned process so a tool authenticates **without the agent ever seeing a durable secret value** — worst case a probe sees only a scoped near-expiry token, itself captured in the audit trace.

## Scope
**In:** executor-side injection at exec time for the common patterns — AWS via the container-credentials endpoint (`AWS_CONTAINER_CREDENTIALS_FULL_URI`) so AWS CLIs/SDKs work unmodified; GCP/Azure via env injection at spawn (v1); per-session identity; zero-broker-memory-after-inject; `cred.resolve` audit.
**Out:** the L7 HTTP header-injection proxy (F5.2), the specific cloud AssumeRole/impersonation adapters (F5.3), OAuth2 (F5.4). This wires the injection *mechanism* + the AWS-endpoint path; adapters plug into it.

## Implementation approach
1. **Resolve + scope:** at exec, for each `creds` grant the resolved policy allows, resolve the secret from the F5.6 vault, and (via an adapter, F5.3) exchange it for a **scoped, short-lived** credential (TTL-bounded). Never inject the raw long-lived secret when a scoped exchange exists.
2. **AWS container-credentials endpoint:** the daemon serves a loopback metadata endpoint the sandbox reaches only through a pinned address, exposing short-lived creds; inject `AWS_CONTAINER_CREDENTIALS_FULL_URI` (+ a per-session auth token) into the process env so `aws`/SDKs fetch creds unmodified. The raw secret is never in the container.
3. **GCP/Azure (v1):** env injection of a short-lived token at spawn (metadata-server emulation is a stretch goal); documented as env-visible-but-short-lived until the proxy/metadata path lands.
4. **Zero after inject:** the broker zeroes the plaintext from its memory immediately after injecting (best-effort in Go); the injected artifact is scoped + near-expiry.
5. **Audit:** emit `cred.resolve{ref, provider, scope, ttl, success}` (F5.6) — never the value.

## Tools & libraries
Go, the F5.6 vault + `cred.resolve`, the session manager exec/spawn path, the F5.3 adapters (AWS STS etc.), a small loopback creds endpoint (net/http on a pinned address reachable only from the session).

## Acceptance criteria (testable)
- [ ] `aws s3 ls` (or an SDK call) succeeds in a granted session with **no AWS access key in the container env/files** — only the container-credentials endpoint + a scoped token.
- [ ] A red-team probe inside the sandbox cannot recover a durable plaintext secret — at most a scoped, near-expiry token, which is itself in the `cred.resolve` trace.
- [ ] Injection happens only for policy-granted creds (deny-by-default from F5.6/F4.1); an ungranted tool call gets no credential.
- [ ] The broker zeroes the plaintext after injection; the raw secret never appears in env/argv/logs/trace.
- [ ] TTL-bounded: the injected credential expires; an expired session can't reuse it.

## QA checklist
- [ ] Adversarial in-sandbox probe (env dump, /proc, files, the creds endpoint) recovers no durable secret — only a scoped short-lived token; documented what IS visible.
- [ ] The AWS container-credentials endpoint is reachable only from the owning session (pinned address + per-session token), not cross-session or from the host network.
- [ ] Ungranted resolve fails closed; the scoped-exchange path is used when available (no raw-secret injection when a token exchange exists).
- [ ] Zeroing + no-log of the plaintext verified; `cred.resolve` carries no value.
- [ ] Works unmodified for a real AWS CLI/SDK against a stub STS (integration-gated).

## Security considerations
- **This is where credential-blindness becomes real** — the agent authenticates without holding a durable secret. Be honest about the v1 residual: GCP/Azure env injection is short-lived-but-agent-visible until the proxy/metadata path (F5.2) lands; only the AWS endpoint path is fully blind in v1.
- The loopback creds endpoint is a trust boundary: scope it to the owning session (per-session token + pinned address); it must not leak creds cross-session or to the host.
- Scoped + short-lived is the containment: even a worst-case in-sandbox capture yields a near-expiry, minimally-scoped token, fully audited — never the crown-jewel secret.
