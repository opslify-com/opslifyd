# F5.2 — L7 egress proxy (credential-blind HTTP injection)

**Phase:** P5 · **Status:** todo · **Owner:** Builder (Go) · **Depends on:** F5.1 · **Blocks:** F5.5

> Research-flagged as the **hardest** surface. Build after F5.1.

## Goal
All sandbox HTTP(S) flows through a daemon proxy that injects `Authorization` (and other auth) headers **at the network boundary** — so a token is added *after* traffic leaves the sandbox and the agent never sees it, even for generic HTTP APIs and private git.

## Scope
**In:** an L7 proxy the session's egress is routed through; TLS-terminating (per-session CA injected into the sandbox trust store) for header-injection targets, SNI-validated pass-through elsewhere; policy on method+host+path; upload byte caps + entropy scoring → `egress.anomaly`; `cred.resolve` on each injection. Non-HTTP stays default-deny + DNS pinning (F1.4).
**Out:** the vault/adapters (F5.6/F5.3), the package registry proxy (F5.5 — but this feature must not break checksum verification; route those to F5.5).

## Implementation approach
1. **Routing:** the sandbox's HTTP(S) egress goes to the daemon proxy (reconciles with F1.4 default-deny; the proxy is the allowlisted egress path). Per-session CA minted at create, injected into the session trust store so TLS-terminate works for injection targets.
2. **Injection:** for a policy-granted host, resolve the secret (F5.6) → inject the auth header on the outbound request; the token never returns to the sandbox. SNI-validated pass-through for hosts we must not MITM.
3. **Known conflict (handle explicitly):** TLS interception breaks out-of-band signature/checksum verification (Terraform providers, package managers). Do NOT MITM those — route through the F5.5 registry proxy; document the split.
4. **Anomaly:** per-session upload byte caps + entropy scoring on outbound bodies → `egress.anomaly` events (exfil signal).
5. **Audit:** `cred.resolve` + egress events; the injected token is never traced/logged raw.

## Tools & libraries
Go (`net/http`, `crypto/tls` — reverse/forward proxy), per-session CA, the F5.6 vault, F1.4 egress, the F3.1 recorder.

## Acceptance criteria (testable)
- [ ] A private GitHub clone (or a generic authenticated HTTP API) works via proxy header injection — **the token never appears in the sandbox** (env/files/proc).
- [ ] Injection only for policy-granted host+path; ungranted → no header, default-deny still applies.
- [ ] TLS-terminate targets get the per-session CA; pass-through targets are SNI-validated and NOT MITM'd.
- [ ] Checksum/signature-verifying tools are routed to F5.5 (not MITM'd) — a documented, tested split.
- [ ] Oversized/high-entropy uploads raise `egress.anomaly`; the injected token never appears in a trace/log.

## QA checklist
- [ ] In-sandbox probe cannot recover the injected token (it is added after egress); documented residual.
- [ ] The per-session CA is scoped to the session and cannot sign for other sessions/hosts; pass-through can't be downgraded to MITM a checksum-verifying target silently.
- [ ] Policy host+path matching is fail-closed; non-HTTP stays default-deny + DNS-pinned (F1.4 intact).
- [ ] Anomaly scoring can't be trivially evaded to exfil unbounded data without an event (characterize).
- [ ] No token in any trace/log; `cred.resolve` carries no value.

## Security considerations
- **The hardest, highest-value credential-blind surface** — generic HTTP auth without the agent seeing the token. Be explicit about the MITM-vs-checksum conflict and route those to F5.5 rather than silently breaking verification.
- The per-session CA is a trust boundary: minted per session, injected read-only, never reusable across sessions.
- This proxy is the credential-blind path for GCP/Azure/generic HTTP that F5.1's env injection only approximates; document what becomes fully blind once it lands.
