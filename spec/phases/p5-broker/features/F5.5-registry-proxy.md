# F5.5 — Package registry proxy (supply-chain + checksum-safe path)

**Phase:** P5 · **Status:** in-progress · **Owner:** Builder (Go) · **Depends on:** F5.2 · **Blocks:**

## Goal
Route `pip`/`npm`/`go` (and Terraform provider) fetches through a daemon **caching registry proxy** with an allowlist + attestation, so the broker can authenticate to private registries **without** the F5.2 TLS-MITM breaking package checksum/signature verification — closing the poisoned-dependency exfil path and the checksum-vs-MITM conflict.

## Scope
**In:** a daemon-side registry proxy for pip/npm/go (index-url / registry / GOPROXY pointed at it), an allowlist + Sigstore/attestation check, `pkg.install` hash events, and credential injection for private registries that does NOT break out-of-band verification.
**Out:** the generic L7 proxy (F5.2 — this is the checksum-safe complement), cloud adapters (F5.3). Not a full artifact repository.

## Implementation approach
1. **Proxy:** point the sandbox's `pip`/`npm`/`go` at the daemon proxy (index-url, npm registry, `GOPROXY`), caching upstream. Private-registry auth is injected daemon-side (not MITM'd end-to-end), so package signatures/checksums still verify.
2. **Allowlist + attestation:** only allowlisted packages/registries; verify Sigstore/attestation where available; refuse unattested where policy requires.
3. **`pkg.install` events:** emit a hash event per installed package (name, version, hash) into the trace — supply-chain evidence.
4. **Conflict resolution:** this is where the F5.2 "don't MITM checksum-verifying tools" split lands — those tools route here instead.

## Tools & libraries
Go (`net/http` caching proxy), Sigstore/attestation verification, the F5.6 vault (private-registry creds), F3.1 audit (`pkg.install`), F5.2 (routing split).

## Acceptance criteria (testable)
- [ ] `pip`/`npm`/`go` installs flow through the daemon proxy; a private-registry fetch authenticates **without breaking checksum/signature verification**.
- [ ] Only allowlisted packages/registries resolve; an un-allowlisted fetch is refused.
- [ ] Each install emits a `pkg.install` hash event (name/version/hash) into the trace.
- [ ] A package failing attestation (where required) is refused (fail-closed).
- [ ] The private-registry credential never appears in the sandbox.

## QA checklist
- [ ] Checksum/signature verification still passes through the proxy (the F5.2 MITM conflict is genuinely resolved, not bypassed).
- [ ] Allowlist + attestation are fail-closed; an unattested/poisoned package can't slip through when policy requires attestation.
- [ ] `pkg.install` hashes are accurate + chained (F3.1); tamper-evident supply-chain record.
- [ ] Registry credential injection leaks nothing to the sandbox.
- [ ] Cache poisoning / path traversal in the proxy cache is not possible (adversarial).

## Security considerations
- **Closes two holes at once:** the poisoned-dependency exfil path (allowlist + attestation + hash events) and the checksum-vs-MITM conflict from F5.2 (checksum-verifying tools route here, un-MITM'd).
- Private-registry creds are injected daemon-side, never in the sandbox.
- `pkg.install` hash events make the installed dependency set part of the tamper-evident audit — supply-chain evidence for compliance.
