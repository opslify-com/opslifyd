# F5.8 — Sandbox↔broker reachability (bridge-gateway bind + source-IP scoping)

**Phase:** P5 · **Status:** approved · **Owner:** Builder (Go) · **Depends on:** F5.1, F5.7 · **Blocks:**

## Goal
Make the broker's per-session listeners (F5.1 AWS creds endpoint + F5.7 egress proxy) actually **reachable from inside the sandbox** — bound to the podman **bridge gateway** the container can route to (not the daemon's `127.0.0.1`, and NOT `0.0.0.0`), source-scoped to the owning container's IP — and advertise that gateway address in the sandbox env. This is the last mile that turns the credential-blind path from "unit-proven" into "works end-to-end on a real host."

## Scope
**In:** the F0.3 runtime seam to discover a container's gateway + IP (podman inspect); binding the F5.1 creds endpoint + F5.7 proxy listener to a **container-reachable** address (the bridge gateway); a source-IP allow (only the owning container's IP); advertising the gateway address in the injected env (`AWS_CONTAINER_CREDENTIALS_FULL_URI`, `HTTPS_PROXY`).
**Out:** the injection logic itself (F5.1/F5.7 — done), the egress allowlist for the daemon→upstream leg (F1.4 config / `--insecure-no-egress` for the first smoke test), gVisor-tier netstack specifics (target the `local-docker`/runc tier first; document gVisor as a follow-up).

## Implementation approach
1. **Runtime gateway/IP discovery:** extend the `Runtime` seam (or a capability like `ImageRemover`) with `NetworkInfo(handle) (containerIP, gatewayIP string, err)` implemented for podman via `podman inspect --format '{{.NetworkSettings.IPAddress}} {{.NetworkSettings.Gateway}}'`. The fake runtime returns test values. This fills the `sandboxIP` seam the manager already reserved.
2. **Reachable bind:** the F5.1 `CredServer` and the F5.7 proxy listener bind the **gateway IP** (reachable from the container on that bridge) rather than `127.0.0.1`. NEVER `0.0.0.0`. If the gateway can't be discovered, fail closed (no endpoint, no proxy env — the blind path is simply unavailable, never a raw-secret fallback).
3. **Source-IP scoping:** each listener only serves requests whose source IP == the owning container's IP (in addition to F5.1's per-session bearer token). A request from any other address (another container, the LAN) is refused — so binding to the bridge gateway can't be abused by a neighbour.
4. **Advertise the gateway in env:** `AWS_CONTAINER_CREDENTIALS_FULL_URI=http://<gw>:<port>/...` and `HTTPS_PROXY=http://<gw>:<port>` use the gateway address (still no token — F5.1/F5.7 unchanged otherwise). `NO_PROXY` keeps the creds endpoint direct.
5. Wire discovery into `registerReady` before the endpoints are built; keep it opt-in (no gateway / no rules ⇒ no change).

## Tools & libraries
Go, the F0.3 `Runtime` seam (+ podman inspect), the F5.1 `CredServer` + F5.7 proxy listener, the session manager `registerReady`/`sandboxIP` seam.

## Acceptance criteria (testable)
- [ ] The F5.1 creds endpoint + F5.7 proxy bind the discovered **gateway IP** (a container-reachable address), never `127.0.0.1` or `0.0.0.0`; the injected env advertises that gateway address (unit-tested with a fake runtime returning a gateway/IP; assert the bind addr + env host == gateway, not loopback/0.0.0.0).
- [ ] A request to a listener from a source IP other than the owning container's is refused (source-IP scope), even with a valid token.
- [ ] Gateway discovery failure fails closed: no endpoint/proxy env, no raw-secret fallback.
- [ ] Still no token in the sandbox (F5.1/F5.7 invariants intact); per-session listeners torn down on end.
- [ ] **(Integration, live host):** from inside a runc sandbox, `curl` to the gateway proxy address reaches the daemon and a granted `curl https://gitlab.com/...` returns the authenticated response — documented manual-test steps + the podman-networking caveats.

## QA checklist
- [ ] Bind address is the container-reachable gateway ONLY — never `0.0.0.0` (a routable/world bind of the credential-injecting proxy is BLOCKING); source-IP scope enforced (a neighbour container can't use it).
- [ ] Gateway discovery is behind the runtime seam (fake in tests); a discovery/inspect failure fails closed.
- [ ] F5.1 token gate + F5.7 no-token invariants unchanged; per-session teardown closes the listeners.
- [ ] runc tier targeted; gVisor netstack path honestly documented as a follow-up (not claimed).
- [ ] No regression to F1–F4, F5.1–F5.7.

## Security considerations
- **Binding the credential-injecting listeners is a trust boundary.** They must bind ONLY the bridge gateway (container-reachable, not LAN-routable in a default podman setup) AND enforce a **source-IP == owning-container** check on top of the per-session token — so binding off-loopback can never let another container or a LAN host use the daemon to inject your credential. `0.0.0.0` is forbidden.
- **Fail-closed:** no gateway ⇒ the blind path is unavailable (no endpoint/proxy), never a fallback that puts the secret in the sandbox env.
- Real bridge reachability + the daemon→upstream egress leg are environment-specific (podman/runc here; gVisor netstack is a documented follow-up) and verified on a live host.
