# F2.3 — Claude Code quickstart

**Phase:** P2 · **Status:** in-progress · **Owner:** Builder (Go) · **Depends on:** F2.1, F2.2

## Goal
A documented, copy-pasteable path for a new user to point Claude Code (or any MCP client) at opslify and complete a real task — the "connect Claude Code and do real work in <15 min" north-star surface.

## Scope
**In:** `.mcp.json` snippet, an example task walkthrough, README/quickstart doc, wired to the F2.1 `opslifyd mcp` server + F2.2 modes.
**Out:** the MCP server itself (F2.1); marketing site.

## Implementation approach
1. **`.mcp.json` snippet** that registers the opslify MCP server (`opslifyd mcp`, stdio) so Claude Code auto-discovers the tools. Include the socket path and any flags.
2. **Walkthrough** (README section): install → `opslify init` (pick tools) → start daemon → add `.mcp.json` → in Claude Code, run an example task ("clone repo X, run its tests, report failures") using only opslify tools → show the live CLI (`opslify session ls`) reflecting the agent's sessions.
3. **Example task** that exercises create → exec → (workspace persist) → end, and demonstrates the escape-suite/trust story ("the agent ran this inside a hardened gVisor sandbox — verify with the escape suite").
4. Keep it honest: document what's real (hardened sandbox, egress default-deny) and what's later (credential broker is P5).

## Tools & libraries
Markdown docs; the F2.1 MCP server; `opslify` CLI.

## Acceptance criteria (testable)
- [ ] A new user, following ONLY the quickstart doc, reaches a working opslify session driven by Claude Code (validated on a clean machine or by a reviewer following the steps).
- [ ] The `.mcp.json` snippet is valid and auto-registers the tools (an MCP client lists the opslify tools from it).
- [ ] The example task completes end-to-end using only opslify tools.

## QA checklist
- [ ] Steps are complete and ordered — no missing prerequisite; a reviewer can follow them cold.
- [ ] `.mcp.json` is valid JSON and correct for Claude Code's MCP config.
- [ ] Claims in the doc match reality (no overstating; P5 creds noted as future).
- [ ] Links to the public escape suite ("verify our claims yourself").

## Security considerations
- The quickstart must not instruct users to weaken the sandbox (e.g. `--insecure-no-egress`) except clearly marked dev-only steps.
