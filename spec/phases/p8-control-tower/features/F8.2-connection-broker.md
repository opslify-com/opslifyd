# F8.2 — Connection broker (kinds beyond HTTP)

**Phase:** P8 · **Status:** planned · **Owner:** Builder (Go) · **Depends on:** F5.6, F5.7, F5.9, F8.1, F8.3 · **Blocks:** F8.8

## Goal
Generalise credential-blindness past HTTP headers. Introduce one **Connection** abstraction with
pluggable **kinds**, so a sandbox can reach Kubernetes and SSH hosts under the same rule P5 already
proves for HTTP: **the daemon holds the credential and hands the sandbox the smallest thing that still
works.** v1 ships `http`, `kubernetes`, `ssh`.

## The invariant every kind must satisfy
A kind ships only if it can answer, in one line, **what the sandbox actually receives** — and that
thing must be useless off this host. A kind that can only answer "the credential" does not ship.

| Kind | Mechanism | Sandbox receives | Audit event |
|---|---|---|---|
| `http` | L7 egress proxy injects the header upstream (F5.2/F5.7, existing) | nothing | `cred.resolve` |
| `kubernetes` | generated kubeconfig points at the session proxy; token/mTLS added upstream | a kubeconfig with **no credential in it** | `k8s.request` |
| `ssh` | daemon-held `ssh-agent`, socket forwarded, key destination-constrained | an agent socket — **signatures only** | `ssh.sign` |
| `cloud` | STS AssumeRole / SA impersonation, scope-down policy (F5.3, existing) | short-lived scoped credentials | `cred.resolve` |
| `database` | *(declared, deferred)* terminating auth proxy | a local socket, no password | `db.session` |
| `network` | *(declared, deferred)* daemon holds the tunnel | a route, no tunnel key | `net.route` |

## Scope
**In:**
- A `Connection` interface in `internal/broker`: `Kind()`, `Validate()`, `BuildForSession(sessionID, resolved policy, recorder, netinfo) (Injection, io.Closer, error)`, where `Injection` carries env, files to write into `/workspace`, and listeners to bind. Each kind is a separate implementation registered by name; adding a kind touches no session code.
- **`kubernetes` kind.** The daemon generates a kubeconfig whose `server:` is the per-session proxy and whose user block is **empty**, writes it to a daemon-controlled path, and sets `KUBECONFIG`. The proxy terminates TLS and injects the real bearer token / client cert upstream. Reuses the F5.7 per-session CA and the F5.9 gateway bind + source-IP scope.
- **`ssh` kind.** The daemon runs an `ssh-agent` **outside** the sandbox holding the key, adds it with **destination constraints** (`ssh-add -h <dest> -H <known_hosts>`, OpenSSH 8.9+) restricted to the connection's declared hosts, and forwards **only the socket** in via `SSH_AUTH_SOCK`. Every signing request is policy-checked and recorded as `ssh.sign` with the target host-key fingerprint from `session-bind@openssh.com`.
- Connection records are **project/environment-scoped** (F8.1) and reference a **secret by ref** (F8.3) — never an inline value.
- CLI: `opslify connection add|ls|rm|test`, kind-specific flags.

**Out:**
- `database` and `network` implementations (interface declared; see the roadmap).
- Session recording/replay for SSH (we record authentications and daemon-launched commands, not interactive session content — see Security).
- Becoming a jump host / terminating SSH; and reimplementing an SSH CA (see "Prior art" below).

## Implementation approach
1. **Interface + registry first**, with `http` refactored onto it so the abstraction is proven against a working kind before new ones are written.
2. **`kubernetes`**: generate kubeconfig → bind proxy on the F5.9 gateway → inject `KUBECONFIG`. Must pass HTTP `Upgrade` through (SPDY/WebSocket) or `kubectl exec/attach/port-forward/cp` break while everything else works — an explicitly confusing failure, so it gets its own test.
3. **`ssh`**: agent lifecycle per session; key loaded with destination constraints derived from the connection's host list; `SSH_ASKPASS` pointed at a daemon policy binary so `ssh-add -c` becomes machine-speed per-signature authorization. Fail-closed: no constraint → no key loaded.
4. **Teardown** closes agent, listeners and proxy with the session; no artefact outlives it.

## Acceptance criteria (testable)
- [ ] `http` behaves exactly as before the refactor (no regression to F5.7/F5.9).
- [ ] `kubernetes`: the kubeconfig written into the sandbox contains **no credential** (asserted by parsing it); `kubectl get pods` succeeds through the proxy; the bearer token appears only on the upstream request, never in the sandbox env, the file, or the trace.
- [ ] `kubectl exec` and `port-forward` work through the proxy (HTTP Upgrade passthrough), covered by their own test.
- [ ] `ssh`: no private key material exists anywhere in the sandbox (filesystem or env); `ssh <allowed-host>` succeeds; a signing request for a host **outside** the destination constraint is **refused** and recorded.
- [ ] Every signature emits `ssh.sign` with target fingerprint, key id and allow/deny, into the verifiable chain.
- [ ] A connection referencing a missing/unreadable secret **fails closed**: no injection, no fallback.
- [ ] Connection scope may be narrowed by policy but never widened by a workspace file.
- [ ] **(Integration, live host):** documented manual test for `kubernetes` and `ssh` against a real cluster and a real VM, like `F5.7-...-LIVE.md`.

## QA checklist
- [ ] For each shipped kind, the "sandbox receives" claim is asserted by a test that greps the sandbox env, injected files and the trace for the credential — not merely reasoned about.
- [ ] SSH destination constraints are actually applied (a permissive fallback when constraints cannot be set is BLOCKING — fail closed instead).
- [ ] The agent socket is the only SSH artefact in the sandbox; no key, no `~/.ssh` copy, no ProxyJump credential.
- [ ] Generated kubeconfig cannot be pointed at anything but the session proxy (no user-supplied `server:` override reaching it).
- [ ] Per-session teardown removes agent + listeners; nothing survives session end; no rule/socket leak across sessions.
- [ ] No regression to F5.6 vault write-only, F5.7/F5.9 egress, F7.x.

## Security considerations
- **The SSH agent protocol has no export operation** (add/remove/list/sign/lock), so key material genuinely cannot cross the socket. The classic agent-forwarding risk — a hostile client using the socket as an unrestricted signing oracle — is exactly our threat model, and **destination constraints are the mitigation**: the binding is anchored by `session-bind@openssh.com`, which carries the target's signature over the session identifier *using its host key*, so a compromised sandbox cannot forge which host it is authenticating to.
- **Constrained agent forwarding is preferred over minting certificates** for v1: nothing bearer-shaped enters the sandbox, revocation is removing the key or the socket, and we get **one audit record per authentication** rather than one per issuance. Short-lived certs remain the right tool where per-*command* scoping is needed (`force-command`) — a later addition, not v1.
- **Prior art is real.** Teleport, Boundary and StrongDM already broker credential-blind SSH/k8s/DB with session recording and replay. What differs here is the inversion — *the client is the threat* — which is why an exotic OpenSSH feature is our first-class primitive. **Integrating an existing CA (Boundary/Teleport) is explicitly preferred over building one** if certificates become necessary.
- **Honest limits.** SSH session content is end-to-end encrypted: we see every authentication and every daemon-launched command, not the inside of an interactive session. And transport blindness does not prevent **exfiltration by authorised read** (`kubectl get secret`, `vault kv get`) — the mitigation is response-side filtering where we terminate the protocol, and the gap is stated where we do not.
