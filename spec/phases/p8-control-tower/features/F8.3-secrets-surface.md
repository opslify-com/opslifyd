# F8.3 — Secrets surface (the reference model)

**Phase:** P8 · **Status:** planned · **Owner:** Builder (Go + SPA) · **Depends on:** F5.6, F8.1 · **Blocks:** F8.2, F8.8

## Goal
Make explicit where a **reference** comes from: you store a value once and never read it back; what
you get is a name. Everything downstream — connections, policy, config, the agent — uses the name,
which is why the name is safe to write in a file or hand to an agent.

## Scope
**In:** project-scoped listing of secret refs with provider, created/last-used, **which connections
consume each ref**, and rotation; an add flow whose value input is write-only; optional sync from an
external manager (Vault/OpenBao/Doppler/ASM/Key Vault) into the local vault. Wraps the existing F5.6
vault; UI behind F7.1 token auth.
**Out:** any read path to a value (forbidden); native external-manager backends at inject time
(sync-in only — the `SecretBackend` interface remains the extension point); the master key, which
stays CLI-only per F7.2.

## Secret vs connection
A **secret** is the value. A **connection** is how it reaches an upstream. One secret may back several
connections (`ssh-ops-fleet` backing both the web fleet and db-01, each with its own destination
constraint) — which is why rotating a key is one action rather than an edit in six places.

## Acceptance criteria (testable)
- [ ] No API/UI/socket route returns a secret value (enumerated and asserted, as in F5.6/F7.2).
- [ ] Add accepts a value from stdin/file/paste and confirms storage **without echoing it**; the value never reaches the trace or a log.
- [ ] The list shows consuming connections per ref, and refuses deletion of a ref still in use (or requires an explicit force that also removes the connections).
- [ ] Rotation replaces the value in place: existing connections keep working by ref, and the rotation is recorded as an audit event with no value.
- [ ] Sync-from-manager writes through the same write-only path; a failed sync leaves the previous value intact.

## QA checklist
- [ ] Value never appears in: HTTP responses, the SPA bundle or DOM, the trace, daemon logs, shell history (stdin/file only).
- [ ] Deleting a secret in use fails closed rather than silently breaking connections at next session.
- [ ] No regression to F5.6 at-rest encryption or F7.2 key handling.

## Security considerations
- The write-only property is the product. Adding a convenient "reveal" for the operator would put a
  read path on a local-network-reachable surface and is refused — `opslify vault key export` (F7.2)
  is the only key path, and it is CLI-only and local.
- Rotation must never leave a window where a connection resolves a half-written value; write is atomic
  or it does not happen.
