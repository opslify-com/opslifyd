# F4.1 — `opslify.policy.yaml` (declarative policy + schema)

**Phase:** P4 · **Status:** approved · **Owner:** Builder (Go) · **Depends on:** F3.1 · **Blocks:** F4.2

## Goal
A declarative, schema-validated policy file that governs a session — session limits, what commands are allowed, what needs human approval, egress domains, and (later) credential grants — loaded from the workspace repo root or a daemon default, with **line-level** validation errors. The resolved policy's `policy_hash` is bound into every session's trace so the audit record proves which policy was in force.

## Scope
**In:** the `opslify.policy.yaml` schema + loader + validator, the resolved in-memory policy model, `policy_hash` computation and its wiring into the F3.1 session-binding, and the CLI to lint a policy (`opslify policy check`).
**Out:** enforcement (F4.2), approval gates (F4.3), dry-run (F4.4), credential grants (parsed here as a `creds` section but only enforced in P5). No OPA/Rego yet (a documented future option).

## Implementation approach
1. **Schema** (sections): `session` (ttl, tier/runtime, image), `allow` (kubectl namespaces/verbs, terraform commands, generic argv regexes), `approval_required` (command patterns that force a human gate), `egress` (allowed domains — reconciles with F1.4), `creds` (refs/providers — parsed + validated now, enforced in P5). Flags: `strict_exec: true` (exec becomes allowlist-only; default is allow-with-approval_required), deny-by-default for `creds`.
2. **Loader/precedence:** workspace `opslify.policy.yaml` (repo root of the mounted `/workspace`) overrides the daemon default policy; a documented, deterministic merge (workspace narrows, never widens, the daemon policy — a workspace file must not be able to grant itself more than the daemon allows).
3. **Validation:** parse with a YAML lib that preserves line/col; validate against a JSON-schema (or hand-rolled validator) and emit **line-level** errors (`policy.yaml:12: unknown verb "destroy" in allow.kubectl.verbs`). Fail fast — the daemon/session refuses to start on an invalid policy rather than silently ignoring rules.
4. **`policy_hash`:** canonical-serialize the *resolved* policy and SHA-256 it; write it into the F3.1 session-binding (the `policy_hash` slot F3.1 reserved) so every trace chains to the exact policy. An empty/default policy has a stable, well-known hash.
5. **CLI:** `opslify policy check [path]` lints a file and prints line-level errors or "ok" + the `policy_hash`.

## Tools & libraries
Go, a line-preserving YAML parser (e.g. `gopkg.in/yaml.v3` with node positions), JSON-schema or a typed validator, the F3.1 trace binding, the existing config loader pattern (`internal/install`).

## Acceptance criteria (testable)
- [ ] A valid policy loads into the resolved model with all sections parsed.
- [ ] **A syntax/semantic error fails fast with a line-level message** (file:line: reason).
- [ ] Workspace policy narrows but cannot widen the daemon default (a workspace grant beyond the daemon policy is rejected or clamped, with a logged reason).
- [ ] `policy_hash` is deterministic for a given resolved policy and is written into the session trace binding (verifiable via `opslify verify` / the trace).
- [ ] `strict_exec: true` is parsed and surfaced to enforcement (F4.2 consumes it).
- [ ] `opslify policy check` returns line-level errors or ok + hash.

## QA checklist
- [ ] Deterministic canonical serialization → stable `policy_hash` across runs/Go versions (mirror the F3.1 canonicalization discipline).
- [ ] Precedence is safe: no workspace file can escalate privilege beyond the daemon policy (adversarial test: a malicious workspace policy granting extra namespaces/egress is clamped/rejected).
- [ ] Invalid YAML, unknown keys, wrong types, and out-of-range values all produce legible line-level errors (table-driven).
- [ ] An absent policy file yields the documented default (deny-by-default creds; exec default-allow) with a stable known hash.
- [ ] Enforcement (F4.2) can consume the resolved model without re-parsing.

## Security considerations
- **The workspace is agent-controlled**, so `opslify.policy.yaml` from `/workspace` is untrusted input: it may only *narrow* the daemon policy, never widen it. This is the critical invariant — an agent must not grant itself capabilities by editing its own policy file.
- Policy binding (`policy_hash` in the trace) is what lets an auditor prove which rules were enforced for a session; it must be the *resolved* policy, not just the file bytes.
- Fail-closed: an unparseable/invalid policy refuses to serve the session rather than defaulting to permissive.
