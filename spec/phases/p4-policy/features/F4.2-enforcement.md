# F4.2 — Enforcement points (session + exec interception)

**Phase:** P4 · **Status:** in-progress · **Owner:** Builder (Go) · **Depends on:** F4.1 · **Blocks:** F4.3

## Goal
Actually enforce the F4.1 policy at the two points that matter: **session spin-up** (egress domains, tier/runtime, ttl) and **every exec** (argv pattern match before the process is spawned). A disallowed command is refused before it runs, and every allow/deny decision is written to the trace as a `policy.decision` event.

## Scope
**In:** wiring the resolved policy into the session manager (spin-up constraints) and an **exec interceptor** that matches argv against `allow` / `approval_required` / `strict_exec` before spawn; emitting `policy.decision` trace events; returning a structured deny to the caller (CLI/MCP).
**Out:** the human approval loop itself (F4.3 — this feature only *classifies* a command as allow/deny/needs-approval), dry-run rewrites (F4.4), credential scoping (P5). No new sandbox primitives (reuses F1/F2).

## Implementation approach
1. **Session spin-up:** at create, apply the policy `session` (ttl, tier/runtime, image) and `egress` (reconcile with F1.4's allowlist — policy egress narrows the daemon egress). A session requesting a tier/image the policy forbids is refused with a legible reason.
2. **Exec interceptor:** before `Runtime.Exec` spawns anything, classify the argv against the resolved policy:
   - matches `approval_required` → return `needs-approval` (F4.3 handles the pause);
   - `strict_exec: true` and not in `allow` → **deny**;
   - default (non-strict) and not otherwise gated → allow;
   - structured command awareness for the known tools (kubectl namespace/verb, terraform subcommand) plus generic argv regex.
3. **`policy.decision` events:** every classification emits a trace event `{decision: allow|deny|needs_approval, rule, argv_summary, policy_hash}` (redacted via F3.3 like any payload). Denials never spawn a process.
4. **Structured refusal:** a deny returns a typed error to the CLI and (via F2.1) to the MCP tool — reason + the rule that fired — so the agent gets an actionable message, never a silent failure.
5. Keep the classifier a pure, table-testable function separate from the spawn path (a decision seam F4.3/F4.4 build on).

## Tools & libraries
Go, the F4.1 resolved policy model, the session manager + `Runtime.Exec` seam, the F3.1 trace sink (`policy.decision` is a reserved type F3.1 already defined), F1.4 egress.

## Acceptance criteria (testable)
- [ ] **kubectl restricted to an allowed namespace: a cross-namespace call is blocked + traced `policy.decision: deny`.**
- [ ] `terraform` subcommands outside `allow` are denied (or routed to approval per policy) before spawn.
- [ ] `strict_exec: true`: a command not in `allow` is denied; with it off, an ungated command runs.
- [ ] Session requesting a policy-forbidden tier/image/egress is refused at spin-up with a legible reason.
- [ ] Every allow/deny/needs-approval emits a `policy.decision` trace event carrying the `policy_hash`.
- [ ] A denied command spawns **no** process and returns a structured reason to CLI + MCP.

## QA checklist
- [ ] The classifier is a pure function, table-tested across kubectl/terraform/generic-argv allow+deny cases (including tricky argv: flags reordered, `--namespace=x` vs `-n x`, quoting).
- [ ] **No bypass:** argv obfuscation (env var indirection, `sh -c`, path tricks, symlinks) cannot slip a denied command past the interceptor — or the residual is documented and the safe default is deny. Adversarial tests.
- [ ] Enforcement happens BEFORE spawn (a denied command never touches the runtime) — verified against the fake runtime (no Create/Exec call on deny).
- [ ] Egress/tier narrowing composes with F1.4/F1.2 without weakening them.
- [ ] `policy.decision` events are redacted (F3.3) and chained (F3.1) like any event.

## Security considerations
- **Unset daemon `session.*` bounds must not let a workspace seed a weaker bound (F4.1 QA carry-over).** F4.1's narrows-not-widens merge clamps `session.tier/ttl/image` only when the *daemon* policy sets them; if the daemon leaves them unset, the workspace value passes through the resolved model unclamped. In F4.1 this is hash-only (enforcement doesn't read it), but F4.2 reads `Resolved.Session` — so the daemon default policy MUST pin `session.tier/ttl/image` from daemon config before enforcement trusts them, or enforcement must fall back to the daemon config bounds (never the workspace-supplied value) when the daemon policy bound is unset. Test the adversarial case: a workspace policy proposing a weaker tier / longer ttl with an unset daemon bound must NOT relax the actual session.
- **Deny must be fail-closed and un-bypassable at the argv boundary** — this is the enforcement teeth. Where argv classification is inherently evadable (a shell wrapper running arbitrary sub-commands), `strict_exec` + an allowlist is the honest strong mode; document the limits of pattern-matching in non-strict mode rather than implying it's airtight.
- The interceptor must not itself become an injection vector (no shelling out to evaluate policy; pure matching).
- Decisions are evidence: a `policy.decision` in the tamper-evident trace is what proves an action was permitted or blocked under a known `policy_hash`.
