# F0.1 — Interactive install & tool selection

**Phase:** P0 · **Status:** in-progress · **Owner:** Builder (Go) · **Depends on:** F0.2 · **Blocks:** F1.1

## Goal
`opslify init` detects the user's project(s), asks which DevOps tools their agents should have, writes config, and drives F0.2 to produce the signed toolchain — the first-run "wow" that makes environments reproducible and minimal.

## Scope
**In:** project detection, interactive tool prompt, `opslify.env.yaml` + `devbox.json` generation, config file, invoking `EnvBuilder`, systemd unit + daemon identity key.
**Out:** the Nix composition internals (F0.2), sandbox creation (P1).

## Implementation approach
1. **CLI** (`cobra`): `opslify init [dir]`.
2. **Project detection:** scan for markers (`main.tf`, `*.tf`, `Chart.yaml`, `kustomization.yaml`, `package.json`, `go.mod`, `requirements.txt`, `Dockerfile`) → suggest a default tool set; user edits via a checklist prompt (`bubbletea`/`survey`).
3. **Tool catalog:** curated list (terraform, kubectl, helm, aws, gcloud, az, docker-cli, git, python3, node, go, jq, curl, ...) each mapped to a Nix package; user may add custom Nix packages.
4. **Outputs:**
   - `opslify.env.yaml` — declared toolset + versions.
   - `devbox.json` / `flake.nix` — handed to F0.2.
   - `/etc/opslify/config.yaml` — `image` (base digest), `session_ttl` (30m), `warm_pool_size` (1), `egress_allowlist`, `workspace_dir`, default `tier` (`local-hardened`).
5. **Daemon bootstrap bits:** verify Podman + runsc present (warn + offer runc fallback if runsc missing), create `opslify` system user, `opslify0` bridge, socket perms 0660 group `opslify`, generate daemon **Ed25519** identity keypair, install systemd unit.
6. Call `EnvBuilder.Compose`+`Bake`; print the resulting signed `layer_digest` + `flake_lock_hash`.

## Tools & libraries
Go, `cobra` (CLI), `bubbletea`/`AlecAivazis/survey` (prompt), YAML, Ed25519 (`crypto/ed25519`), systemd unit template.

## Acceptance criteria (testable)
- [ ] `opslify init` in a Terraform repo suggests terraform+relevant tools by default.
- [ ] User can add/remove tools; result is written to `opslify.env.yaml` + `devbox.json`.
- [ ] A signed toolchain layer is produced (via F0.2) and its digest printed.
- [ ] `/etc/opslify/config.yaml` written with valid defaults; daemon Ed25519 key generated; socket perms 0660/group `opslify` **rendered into the systemd unit** (see scope note).
- [ ] Missing `runsc` produces a clear message + runc-fallback offer, not a crash.

**Scope notes (reconciled after QA):**
- *Socket 0660/group `opslify`* is **declared** by F0.1 (printed note + `RuntimeDirectoryMode` in the systemd unit). The socket itself is created by the daemon at runtime, so **enforcement is verified in P1 (F1.1)**, not here.
- *Creating the `opslify` system user + `opslify0` bridge* (implementation-approach step) requires root and is a **runtime bootstrap concern deferred to P1**; F0.1 surfaces it as guidance and never attempts it in tests.

## QA checklist
- [ ] Detection works for at least: terraform, helm, k8s-manifests, node, python, go projects.
- [ ] Config defaults match spec (ttl 30m, warm_pool 1, tier local-hardened).
- [ ] Re-running `init` is idempotent / prompts before overwrite.
- [ ] No secret material in generated files; identity key file perms 0600.
- [ ] Clean-machine run (fresh Ubuntu) reaches a signed toolchain following docs only.

## Security considerations
- Identity keypair perms 0600, owned by `opslify`. Socket group-gated.
- Never fetch tools from unpinned sources; everything flows through F0.2's signed path.
