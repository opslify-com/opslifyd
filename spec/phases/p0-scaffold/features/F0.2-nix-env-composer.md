# F0.2 — Nix build-time environment composer

**Phase:** P0 · **Status:** in-progress · **Owner:** Builder (Go) · **Depends on:** none · **Blocks:** F0.1, F1.2
**Implements decision:** D1 (Nix as build-time composer only)

## Goal
Turn a declared tool selection into a **reproducible, content-addressed, cosign-signed, read-only** toolchain layer that a sandbox mounts. The `flake.lock` becomes part of the audit attestation. **No tool is ever installed inside a live sandbox.**

## Scope
**In:** `EnvBuilder` interface + impl; devbox/Nix invocation; closure → OCI layer; cosign signing; SBOM; digest recording; verification.
**Out:** the interactive prompt UX (F0.1); mounting into a running sandbox (F1.2).

## Implementation approach
1. **`EnvBuilder` interface** (in `internal/env`), per [architecture.md §6](../../../architecture.md):
   - `Compose(ctx, ToolSelection) (LockedEnv, error)` — write `devbox.json` (or `flake.nix`) from the selection, run `devbox install` / `nix build`, capture `flake.lock`.
   - `Bake(ctx, LockedEnv) (SignedLayer, error)` — export the Nix closure as an OCI image layer (Debian-slim base + Nix store paths), cosign-sign, digest-pin, attach SBOM.
   - `Verify(ctx, SignedLayer) error` — cosign verify signature + digest before any use.
2. **Determinism:** pin nixpkgs via flake input; `flake.lock` fully resolves versions+hashes. Same selection → same digest (reproducible-build target; document any non-determinism).
3. **Layer shape:** toolchain is a separate read-only layer, not baked into the base rootfs — so P1 can mount base(RO) + toolchain(RO) + /workspace(RW).
4. **Attestation record:** persist `{env_id, tool_selection, flake_lock_hash, layer_digest, sbom_ref, signature}` in `/var/lib/opslify/envs/<env_id>.json`. This feeds P3 trace + P6 compliance packs.
5. **Closure-size control:** strip docs/locales where safe; warn if closure > threshold (Nix closures can be fat — a known cost).

## Tools & libraries
- **Nix** (flakes) + **devbox** (UX layer over Nix).
- **cosign / sigstore** (sign + verify), **syft** (SBOM).
- Go: `go-containerregistry` (OCI layer assembly), `cobra` (later CLI wiring), `sigstore/cosign` Go APIs or shell-out to `cosign`.

## Data structures (Go, indicative)
```go
type ToolSelection struct { Tools []Tool; BaseImageDigest string } // Tool{Name, Version?}
type LockedEnv struct { EnvID string; FlakeLock []byte; FlakeLockHash string; ClosurePath string }
type SignedLayer struct { EnvID string; LayerDigest string; SBOMRef string; Signature []byte }
```

## Acceptance criteria (testable)
- [ ] `EnvBuilder.Compose` on `{terraform, kubectl, jq}` produces a `flake.lock` resolving all three + a recorded `flake_lock_hash`.
- [ ] `Bake` produces a cosign-signed, digest-pinned OCI layer with an attached SBOM.
- [ ] `Verify` returns error for a tampered layer (flipped byte) and success for an intact one.
- [ ] Same `ToolSelection` run twice yields the same `layer_digest` (or documented non-determinism with the exact cause).
- [ ] Two different selections yield different digests and different, minimal closures.
- [ ] Attestation record persisted and retrievable by `env_id`.

## QA checklist
- [ ] Tampered layer fails `Verify`; unsigned layer fails `Verify`.
- [ ] `flake.lock` present and hash matches record.
- [ ] SBOM lists exactly the declared tools (+ their transitive deps), nothing unexpected.
- [ ] No network access assumed at *run* time; all resolution happened at build time.
- [ ] Reproducibility check across two clean runs.

## Security considerations
- The signed digest is the trust root for D1 — a weak signing flow undermines the whole product. Keys handled per [shared-engineering.md §5](../../../best-practices/shared-engineering.md).
- Base image is itself digest-pinned + signed (chain of trust to the toolchain layer).
- **Scope note (QA):** `Verify` proves the binding *(stored layer bytes ↔ signed digest)*. The *(env_id ↔ digest)* binding — cross-checking a caller-supplied digest against the persisted attestation record — is the loading daemon's responsibility and is verified where the toolchain is mounted (F1.2), not here.
