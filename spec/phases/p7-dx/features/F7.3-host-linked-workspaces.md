# F7.3 — Host-linked workspaces + auto bidirectional sync

**Phase:** P7 · **Status:** in-progress · **Owner:** Builder (Go) · **Depends on:** F2.2, F3.3 · **Blocks:**

## Goal
Let a developer start a workspace from a **host directory** (e.g. `opslify workspace sync /home/alien/myapp`) and have opslifyd **copy the files into the sandbox `/workspace` and keep them continuously, bidirectionally in sync** — edits on the host flow in, the agent's edits flow back out — **without bind-mounting the host FS into the sandbox** (copy-not-bind, so the isolation the product sells is preserved) and **without copying secrets in**. git is the review/undo safety net; a non-git dir gets a snapshot backup before the first sync-back writes.

## Why copy-not-bind
A bind mount would give sandboxed code direct, live write access to the operator's real filesystem — the exact escape the sandbox exists to prevent. Copy-in + explicit sync keeps a reviewable boundary: the agent only ever touches its `/workspace`, and changes cross back to the host through a controlled, excludable, undoable channel.

## Scope
**In:**
- `opslify workspace sync <host-dir> [--session <id> | --new] [--once]` — a **CLI-side** command that (a) copies the host dir into the target session's `/workspace` (respecting exclusions), then (b) runs a continuous **file-watcher** loop: host changes → upload into `/workspace`; `/workspace` changes → download back to the host dir. `--once` does a single bidirectional reconcile and exits.
- `opslify workspace export <session-id> <host-dir>` — a one-shot pull of `/workspace` out to a host dir (no watch).
- A **workspace manifest** route (`GET /v1/sessions/{id}/manifest`) returning each file's relative path + size + mtime + content hash, so the CLI can diff host vs sandbox without downloading everything. Reuse the existing per-file PUT/GET `…/files` routes for the actual transfer.
- **Secret exclusion on copy-in:** a default deny-list (`.env`, `.env.*`, `*.pem`, `*.key`, `id_rsa*`, `credentials`, `.aws/`, `.git/` internals beyond the tree needed for undo, `.opslify-ca.pem`, anything the F3.3 redaction patterns would flag as high-entropy secret filenames) — never copied INTO the sandbox. Configurable extend/override via a `.opslifyignore` in the host dir (gitignore syntax).
- **git-as-undo safety net:** if the host dir is a git repo, sync-back writes into the working tree and the operator reviews/reverts with normal git; if it is NOT a repo, take a timestamped snapshot copy (or `git init` a shadow repo) before the first sync-back, so an unwanted agent change is always recoverable.
- Conflict handling: last-writer-wins is unacceptable silently — on a both-sides-changed collision, prefer the host copy for host→in and the sandbox copy for out, but **never overwrite a host file that changed since last sync without recording it** (write the sandbox version to a `.opslify-conflict` sibling and warn, rather than clobbering the operator's edit).

**Out:**
- Bind mounts of any kind (forbidden — the whole point).
- The UI directory-linking + sync-toggle button (that is F7.4, safe behind F7.1 auth).
- Real-time sub-second sync guarantees / a custom FS protocol — a debounced watcher (fsnotify) with a periodic manifest reconcile is enough; document the latency.
- Syncing outside the chosen host dir (no `..` escape; symlinks pointing outside the tree are not followed).

## Implementation approach
1. **Manifest route (daemon):** `GET /v1/sessions/{id}/manifest` walks the session `/workspace` (via the existing `m.workspaceRoot`/`ReadFile` seam, path-guarded like `resolveWorkspacePath`), returns `[]{RelPath, Size, ModUnix, SHA256}`. Cap count/size; skip anything outside the workspace root.
2. **Exclusion filter (shared):** one `func excluded(relPath string) bool` used on BOTH copy-in and (as a guard) manifest/pull, built from the default deny-list + `.opslifyignore`. Unit-test that a planted `.env` / `*.pem` never enters the upload set.
3. **CLI sync engine (`cmd/opslify`):** debounced fsnotify watcher on the host dir + a periodic (e.g. 2s) manifest poll of the sandbox. Diff by (mtime, hash): host-newer → PUT into `/workspace`; sandbox-newer → GET and write host; both-changed → conflict handling above. Deletions: propagate host→sandbox deletes; sandbox→host deletes go to a quarantine/warn (don't silently delete the operator's file).
4. **Safety net:** before the first sync-back write to a non-git host dir, create `<dir>/.opslify-backup-<ts>/` (or shadow `git init`) capturing current state; print how to restore. For a git dir, just note "review with git status / git checkout".
5. **Copy-in at start:** `--new` creates a session (reuse `createSession`) then does the initial copy-in; `--session <id>` targets an existing one. Print the sync status (files in, watching, conflicts).
6. **Teardown:** Ctrl-C stops the watcher after a final reconcile; `--once` = single reconcile then exit.

## Tools & libraries
Go, `github.com/fsnotify/fsnotify` (justify the dep in `go mod tidy` — small, standard, cross-platform), the existing `…/files` PUT/GET routes + the new manifest route, the F3.3 redaction pattern set for secret-filename heuristics, the session manager `workspaceRoot`/`resolveWorkspacePath` path guards. Watcher + diff logic lives CLI-side (portable); the daemon only gains the read-only manifest route.

## Acceptance criteria (testable)
- [ ] `opslify workspace sync <dir> --new` copies the host dir into a fresh session's `/workspace` (excluding secrets), then keeps host↔sandbox in sync until interrupted; `--once` does one reconcile and exits.
- [ ] A planted secret file (`.env`, `*.pem`, `id_rsa`, `credentials`) in the host dir is **never** copied into the sandbox (asserted in a test over the exclusion filter and the copy-in set).
- [ ] `GET /v1/sessions/{id}/manifest` returns path+size+mtime+hash for each workspace file, path-guarded (no `..`/symlink escape, capped), and never lists an excluded/out-of-root path.
- [ ] An agent edit inside `/workspace` appears in the host dir after a reconcile; a host edit appears in `/workspace`. Neither side is bind-mounted (assert the runtime bind set has no host-dir mount).
- [ ] A both-sides-changed file does NOT silently clobber the host copy — the sandbox version lands in a `.opslify-conflict` sibling with a warning; a non-git host dir gets a snapshot/backup before the first sync-back.
- [ ] No regression to F2.2 workspaces, F3.3 redaction, F5.7 egress-inject (`.opslify-ca.pem` in `/workspace` is not synced back as a "user file").

## QA checklist
- [ ] **No bind mount of the host dir** anywhere in the sandbox spec (copy-not-bind is the core invariant; a bind mount is BLOCKING).
- [ ] Secret exclusion is fail-safe: the deny-list applies BEFORE any upload; a file matching it is never transmitted to the sandbox even if `.opslifyignore` is malformed/absent. Confirm the `.opslify-ca.pem` / broker-injected files aren't synced back to the host.
- [ ] Manifest + pull are path-guarded (no `..`, no symlink-out, no reading outside `/workspace`); size/count caps prevent a hostile workspace from exhausting the host.
- [ ] Sync-back is undoable: git dir → reviewable via git; non-git dir → backup taken before first write; conflicts never silently overwrite the operator's newer file.
- [ ] Deletions don't let the sandbox silently delete host files (quarantine/warn).
- [ ] The fsnotify dependency is justified, pinned, and `go mod tidy` clean; watcher logic is CLI-side (daemon stays portable-minimal).

## Security considerations
- **Copy-not-bind is the load-bearing invariant.** The convenience of "it feels like a mounted dir" must never become an actual mount — sandboxed code writing straight to the operator's real FS is the escape we exist to stop. All host↔sandbox movement is explicit file transfer through the guarded routes.
- **Secrets never ride in.** The whole product promise is the agent doesn't see credentials; a naive `cp -r` of a project dir would drag `.env`/`.pem` straight into `/workspace`. The exclusion filter is a security control, not a convenience — fail safe (exclude on doubt), applied before transmission.
- **Sync-back is a write to the operator's machine.** It must be reviewable and undoable (git or snapshot), never a silent clobber or a silent delete of host files — the agent's output crosses a trust boundary on the way out.
- **No path escape.** Manifest/transfer stay inside the session `/workspace`; `..` and out-of-tree symlinks are refused, matching the existing `resolveWorkspacePath` guard.
