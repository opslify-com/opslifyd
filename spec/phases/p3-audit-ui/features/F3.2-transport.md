# F3.2 — Transport (local append-only + SSE)

**Phase:** P3 · **Status:** in-progress · **Owner:** Builder (Go) · **Depends on:** F3.1, F3.3 · **Blocks:** F3.4, F3.5

## Goal
Durably persist the F3.1 event stream and make it consumable **live** — an append-only on-disk log per session (the local source of truth, works fully offline) plus a resumable SSE push to the optional cloud backend that survives network cuts with **no event loss**.

## Scope
**In:** the real `TraceSink` impl (in-memory ring buffer + append-only `/var/lib/opslify/traces/<session>.log`), an SSE endpoint on the daemon for local/cloud consumers, offline buffering + backoff + **resume-from-acked-seq** to the cloud, and a read/replay API over stored sessions.
**Out:** the event schema/chain (F3.1), redaction (F3.3 — runs upstream of this), rendering (F3.4/F3.5), auth (cloud/team plane).

## Implementation approach
1. **Append-only file:** one line-delimited JSON record per event under `/var/lib/opslify/traces/<session>.log`, `fsync` policy configurable (default: batch + fsync on `exec.end`/`session.end`). Open `O_APPEND`; never rewrite in place — tamper shows up as an F3.1 chain break, not a silent edit.
2. **Ring buffer:** bounded in-memory tail per live session for instant SSE catch-up without re-reading the file; size configurable, drops only the oldest *buffered* view (never the on-disk record).
3. **Local SSE:** `GET /v1/sessions/{id}/trace?from_seq=N` streams events as they append (and backfills from `from_seq`), so F3.5's local UI and `opslify` consume the same stream with no cloud.
4. **Cloud push (optional):** if a backend URL is configured, an uploader tails each session and pushes over SSE/HTTP with exponential backoff; it tracks the highest **acked seq** per session, buffers offline, and on reconnect **resumes from acked-seq+1**. No backend configured → this is a no-op (local still fully works).
5. **Replay:** `GET /v1/sessions/{id}/trace?from_seq=0` (or a CLI `opslify replay <session>`) yields the full ordered stream for after-the-fact review + `opslify verify`.

## Tools & libraries
Go stdlib (`bufio`, `os` O_APPEND, `net/http` SSE), the F3.1 `TraceSink` seam, existing daemon REST server + Unix socket, configurable fsync/ring-buffer knobs in daemon config.

## Acceptance criteria (testable)
- [ ] Every emitted event lands in `/var/lib/opslify/traces/<session>.log` in `seq` order, one JSON record per line.
- [ ] A local SSE consumer with no cloud configured receives live events and can backfill from an arbitrary `from_seq`.
- [ ] **Network cut mid-session → after reconnect the cloud has every event exactly once** (resume-from-acked-seq; no gaps, no dupes past the ack).
- [ ] Daemon restart mid-session: the on-disk log is intact and replayable; `opslify verify` still passes.
- [ ] With no backend URL configured, transport is a clean no-op and local persistence/stream are unaffected.

## QA checklist
- [ ] Append path is crash-safe (partial last line on power-loss is detected/skipped, not treated as corruption of prior events).
- [ ] Backoff has a cap + jitter; a down backend never blocks the session or unbounded-grows memory (spills to disk buffer).
- [ ] Acked-seq bookkeeping is persisted so resume survives a daemon restart, not just a reconnect.
- [ ] Ring-buffer drops never lose an on-disk event; SSE backfill reads the file when the tail is short.
- [ ] Concurrent sessions don't interleave into each other's log files.

## Security considerations
- Events are persisted **after F3.3 redaction** — raw secrets must never reach disk or the wire. The uploader sends only redacted events.
- Trace files are `0600`, owned by the daemon user; the sandbox has no path to them (not in the workspace mount).
- The cloud channel carries integrity-chained, redacted evidence; loss/dup protection is correctness, and the F3.1 signature lets the backend independently verify nothing was altered in transit.
