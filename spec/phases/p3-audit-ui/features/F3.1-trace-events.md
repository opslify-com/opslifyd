# F3.1 — Trace events (schema v1)

**Phase:** P3 · **Status:** todo · **Owner:** Builder (Go) · **Depends on:** F1.2 · **Blocks:** F3.2, F3.3

## Goal
A per-session, tamper-evident event stream that records everything the agent did — session lifecycle, every exec (argv/cwd/exit/duration), streamed output, and file writes — as a **hash-chained, daemon-signed** log, so any action is cryptographically accountable and replayable. This is the evidentiary spine of the whole P3 "market hero" surface.

## Scope
**In:** the event schema v1, the per-session **SHA-256 hash chain**, Ed25519 signature at session close, the daemon-internal `TraceSink` seam events are emitted to, and binding each session to `image_digest + toolchain_lock_hash` (+ `policy_hash` slot, populated in P4). `opslify verify <session>` chain verification.
**Out:** transport/persistence to disk or cloud (F3.2), redaction (F3.3), any UI (F3.4/F3.5). Policy/cred events are reserved slots only (P4/P5).

## Implementation approach
1. **Event shape:** `{ts, session_id, seq, type, payload, prev_hash, hash}`. `seq` is a per-session monotonic counter starting at 0; `hash = SHA256(canonical(ts, session_id, seq, type, payload) || prev_hash)`; `prev_hash` of `seq 0` is the session-binding digest (`image_digest + toolchain_lock_hash + policy_hash`), so the chain root commits to the environment.
2. **Types (v1):** `session.start` (tier, image_digest, toolchain_lock_hash, agent), `session.end` (reason), `exec.start` (argv, cwd), `exec.output` (stream=stdout|stderr, chunk, offset), `exec.end` (exit_code, duration_ms), `file.write` (path, size). Reserve `policy.decision` (P4) and `cred.resolve` (P5) as known-but-unemitted types.
3. **Emission points:** hook the session manager lifecycle (create/destroy) and the runtime Exec path (start, output chunks, end). File-write events derive from the workspace bind mount where cheaply observable; otherwise deferred with a logged note (do not fabricate).
4. **`TraceSink` interface** (`Append(ctx, event) error`, `Seal(ctx, session_id) (Signature, error)`) — the seam F3.2 implements for real (ring buffer + append-only file). F3.1 ships an in-memory sink + the chain/sign/verify core, fully unit-testable with no I/O.
5. **Sealing:** on `session.end`, append a terminal `hash`, sign the final `hash` with the daemon Ed25519 identity key (reuse F1.1 identity), and record `{final_hash, signature, pubkey_fingerprint}`.
6. **`opslify verify <session>`:** recompute the chain from events, check each `hash`/`prev_hash` link, and verify the sealed signature against the daemon pubkey. Any mismatch → non-zero exit + the first broken `seq`.

## Tools & libraries
Go stdlib `crypto/sha256`, `crypto/ed25519`, `encoding/json` (canonical/sorted marshalling), the existing session manager + runtime Exec seam, F1.1 daemon identity.

## Acceptance criteria (testable)
- [ ] A session produces a well-formed chain: `seq` contiguous from 0, every `hash` recomputes, `prev_hash` links hold.
- [ ] `exec.start/output/end` capture argv, cwd, streamed chunks, exit code, and duration for a real (or faked-runtime) exec.
- [ ] Session close seals + signs the final hash with the daemon identity; `opslify verify` passes on an untampered session.
- [ ] **Editing any event (payload, order, or a hash) makes `opslify verify <session>` fail**, naming the first broken `seq`.
- [ ] The chain root binds `image_digest + toolchain_lock_hash` (policy_hash slot present, empty until P4).

## QA checklist
- [ ] Chain + signature logic is unit-tested against the fake runtime (no disk/cloud).
- [ ] Canonical serialization is stable (map key order can't change a hash across runs/Go versions).
- [ ] `seq`/`prev_hash` are assigned under a per-session lock (concurrent execs can't interleave the chain).
- [ ] Reserved types (`policy.decision`, `cred.resolve`) don't break v1 consumers.
- [ ] `verify` exits non-zero and legibly on: reordering, payload edit, dropped event, bad signature.

## Security considerations
- The signing key is the **daemon identity** (F1.1); the private key never enters an event or the sandbox. Only the fingerprint is recorded.
- Payloads may contain secrets in argv/output — **F3.3 redaction runs before any event is persisted or leaves the daemon.** F3.1 must emit through the sink in a way that lets redaction sit in the path (no direct-to-disk bypass).
- The hash chain proves **integrity + ordering**, not confidentiality; it is the evidence a session's recorded history was not altered after the fact.
