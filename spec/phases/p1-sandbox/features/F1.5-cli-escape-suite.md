## Implementation approach
### CLI
- `opslify run "<cmd>"` (create → exec → print → destroy unless `--keep`)
- `opslify session ls | kill <id> | exec <id> "<cmd>"`
- Talks to `/run/opslify/opslifyd.sock`; clear, layer-labeled error output.

### Escape suite (public repo, from day one)
A matrix of adversarial probes run **inside a session**, expected to FAIL (i.e., be blocked):
- Container escape: docker socket access, root escalation, rootfs write outside `/workspace`, mount tricks, `/proc/<other-pid>` read, ptrace another process, cap probing.
- Exfil: non-allowlisted egress, direct DNS, high-entropy outbound (placeholder for P5 caps).
- Toolchain integrity: attempt in-sandbox install / modify toolchain (must fail — read-only).
- Kernel identity: `uname -r` must show gVisor on `local-hardened`.
- Run the **whole matrix in CI on runc AND gVisor**; publish a per-release results matrix.

## Tools & libraries
Go (`cobra`), shell probe scripts, CI (Dagger/GitHub Actions), results-matrix generator.

## Acceptance criteria
- [ ] `opslify run "kubectl version --client"` works end-to-end.
- [ ] `session ls/kill/exec` behave correctly.
- [ ] Every escape/exfil probe is BLOCKED on gVisor; results recorded.
- [ ] Suite runs in CI on both runc and gVisor and fails the build if any probe unexpectedly succeeds.
- [ ] Public results matrix generated per release.

## QA checklist
- [ ] Add QA's own probes beyond the builder's; all blocked.
- [ ] A deliberately weakened config (e.g., caps not dropped) makes the suite RED — proving the suite has teeth.
- [ ] CLI errors name the layer (sandbox/egress/runtime).
- [ ] No secret in CLI output or suite logs.

## Security considerations
- The suite is a marketing + trust asset, not just a test. It must be honest: a real escape must turn it red. Never weaken a probe to get green.
