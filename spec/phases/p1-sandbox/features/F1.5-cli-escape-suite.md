# F1.5 — CLI + public escape suite

**Phase:** P1 · **Status:** todo · **Owner:** Builder (Go) · **Depends on:** F1.2

## Goal
A usable CLI over the socket, and — critically — the **public escape/exfil test suite** that runs in CI from day one and backs every security claim ("verify our claims yourself").

> **⛔ REAL-ENGINE PREREQUISITES (tracked — do not mark F1.5 startable until scheduled on a podman+runsc host/CI):**
> 1. **(from F1.2 QA)** `podmanRuntime.Exec` must stream stdout/stderr incrementally and return the real exit code — it currently buffers stdout into memory and returns empty stderr + exit 0. Until then: (a) a real-engine failing command reports success, and (b) the end-to-end output-OOM bound isn't enforced (F1.2 caps against the interface, but the runtime accumulates first). The escape suite needs real streaming to verify anything.
> 2. **(from F1.3 QA)** `podmanRuntime.Create` issues `podman create` only (no `start`), but real `podman pause` needs a **running** container. Wire **start-then-pause** so the warm pool's freeze/thaw works against a live engine (F1.3 degrades safely to unpaused-but-hardened today; the true sub-second warm-start + real pause/unpause are unverified until this lands).
>
> 3. **(from F1.4 QA — escape-suite target)** Egress is enforced via an nftables **`forward`-hook** chain. On real nft+netns, verify a sandbox cannot reach a **host-local resolver** (e.g. podman aardvark / `127.0.0.11` / a resolver bound to the `opslify0` IP), which traverses the `input` hook, not `forward` — add an `input`/host-local drop if the runtime injects a local resolver. Also confirm no conntrack helper (FTP etc.) is active in the sandbox netns that could admit new flows via `ct state related`.
>
> **Non-blocking follow-ups (not F1.5 blockers):** `SetToolchainDigest` (F1.3 drain+rebuild) has no production trigger yet — wire it to a toolchain-rotation event when one exists (e.g. re-running `opslify init`/re-bake). `WarmPoolConcurrency` is now wired through config (F1.3 approval). **Egress source-scoping (F1.4)** is bridge-scoped until F0.3's `ContainerHandle` surfaces the per-container IP — the per-session `saddr` rule is inert with multiple concurrent sandboxes on one bridge until then; wire `SandboxIP` once F0.3 exposes the IP.

## Implementation approach
### CLI
- `opslify run "<cmd>"` (create → exec → print → destroy unless `--keep`)
- `opslify session ls | kill <id> | exec <id> "<cmd>"`
- Talks to `/run/opslify/opslifyd.sock`; clear, layer-labeled error output.

### Escape suite (public repo, from day one)
A matrix of adversarial probes run **inside a session**, expected to FAIL (i.e., be blocked):
- Container escape: docker socket access, root escalation, rootfs write outside `/workspace`, mount tricks, `/proc/<other-pid>` read, ptrace another process, cap probing.
- Exfil: non-allowlisted egress, direct DNS, high-entropy outbound (placeholder for P5 caps).
- Toolchain integrity: attempt in-sandbox install / modify toolchain (must fail — read-only).
- Kernel identity: `uname -r` must show gVisor on `local-hardened`.
- Run the **whole matrix in CI on runc AND gVisor**; publish a per-release results matrix.

## Tools & libraries
Go (`cobra`), shell probe scripts, CI (Dagger/GitHub Actions), results-matrix generator.

## Acceptance criteria
- [ ] `opslify run "kubectl version --client"` works end-to-end.
- [ ] `session ls/kill/exec` behave correctly.
- [ ] Every escape/exfil probe is BLOCKED on gVisor; results recorded.
- [ ] Suite runs in CI on both runc and gVisor and fails the build if any probe unexpectedly succeeds.
- [ ] Public results matrix generated per release.

## QA checklist
- [ ] Add QA's own probes beyond the builder's; all blocked.
- [ ] A deliberately weakened config (e.g., caps not dropped) makes the suite RED — proving the suite has teeth.
- [ ] CLI errors name the layer (sandbox/egress/runtime).
- [ ] No secret in CLI output or suite logs.

## Security considerations
- The suite is a marketing + trust asset, not just a test. It must be honest: a real escape must turn it red. Never weaken a probe to get green.
