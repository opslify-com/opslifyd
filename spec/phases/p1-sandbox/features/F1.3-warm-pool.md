# F1.3 — Warm pool

**Phase:** P1 · **Status:** in-progress · **Owner:** Builder (Go) · **Depends on:** F1.2

## Goal
Hit the < 1s warm-start target by keeping N pre-created, paused sandboxes ready to claim.

## Implementation approach
1. Maintain `warm_pool_size` (config, default 1) paused containers pre-mounted with the current signed toolchain.
2. `POST /sessions` claims a warm container (atomically), returns immediately, and triggers background replenishment.
3. On toolchain change (new signed digest), drain + rebuild the pool.
4. Cap replenishment concurrency; never block a claim on replenishment.
5. Reaper also cleans warm containers on shutdown.

## Tools & libraries
Go, Podman pause/unpause, bounded worker pool.

## Acceptance criteria
- [ ] Warm claim yields a ready session in < 1s.
- [ ] Pool replenishes to `warm_pool_size` in the background after a claim.
- [ ] Toolchain digest change drains + rebuilds the pool.
- [ ] No warm containers leak on shutdown.

## QA checklist
- [ ] Concurrent claims don't hand the same container to two callers (atomicity).
- [ ] Warm containers carry the correct signed toolchain digest.
- [ ] Replenishment never starves or blocks claims under load.

## Security considerations
- Warm containers must be identical in hardening to on-demand ones — same hard-spec assertions (F1.2).
