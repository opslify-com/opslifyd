# F1.4 — Default-deny egress + DNS pinning

**Phase:** P1 · **Status:** in-progress · **Owner:** Builder (Go) · **Depends on:** F1.2

## Goal
A sandbox reaches nothing on the network by default; only allowlisted destinations, by IP, with **no direct DNS** from the sandbox. (Full L7 method/path policy is P5; this is L3/L4 + DNS pinning.)

## Implementation approach
1. **nftables default-deny** egress on `opslify0`; static allowlist of resolved IPs from `egress_allowlist` (config).
2. **DNS pinning:** the daemon resolves allowlisted domains and programs the resulting IPs; the sandbox has **no** direct DNS (port 53 blocked). Refresh on TTL; handle multi-A/round-robin.
3. Per-session network namespace attached only to `opslify0`.
4. Legible denials: a blocked connection surfaces as an `egress`-layer error, distinguishable from sandbox/runtime failures.

## Tools & libraries
Go, `nftables` (via `google/nftables` or shelling `nft`), a daemon-side resolver.

## Acceptance criteria
- [ ] From inside a session: connection to a non-allowlisted IP fails.
- [ ] From inside: direct DNS query (`dig @8.8.8.8`) fails.
- [ ] Connection to an allowlisted domain's resolved IP succeeds.
- [ ] Denied egress is reported as an `egress`-layer error.

## QA checklist
- [ ] Allowlist changes take effect without leaking prior rules.
- [ ] DNS-rebinding / round-robin domains handled (all current A records or documented behavior).
- [ ] No path for the sandbox to do its own DNS.
- [ ] Rules torn down cleanly on session destroy (no rule leak).

## Security considerations
- DNS pinning closes the DNS-exfil channel; verify there is no fallback resolver reachable.
- This is a headline escape-suite target (F1.5).
