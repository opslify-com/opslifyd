# F1.2 — Session lifecycle API

**Phase:** P1 · **Status:** todo · **Owner:** Builder (Go) · **Depends on:** F1.1, F0.2, F0.3 · **Blocks:** F1.3, F1.4, F1.5, P2

## Goal
Create hardened per-session sandboxes and execute **mediated** commands in them. The daemon is the **only executor** — every exec is a mediated request (future hook point for policy/trace/cred).

## API
- `POST /v1/sessions {mode, tier?, ttl?}` → `{session_id, state}`
- `POST /v1/sessions/{id}/exec {argv, cwd?, env?, stdin?}` → chunked stream stdout/stderr, then exit code
- `DELETE /v1/sessions/{id}` → destroy
- `GET /v1/sessions` → list {state, age, ttl_remaining}

## Implementation approach
1. Use `ResolveRuntime(tier, location)` (F0.3); default `local-hardened`.
2. **Container hard spec (assert all, never assume):** gVisor runtime, non-root UID 1000, **user-ns remapped** (container root → unprivileged host UID), **read-only rootfs**, mount signed toolchain layer(s) **read-only** + writable `/workspace`, `no-new-privileges`, **all caps dropped**, seccomp default profile, `/proc` hygiene (`hidepid=2`, masked paths, ptrace denied), pids 256, mem 2G / CPU 2 (config), **no Docker socket**, attached only to `opslify0`.
3. **Executor model:** exec spawns the process daemon-side into the container namespace; stream stdout/stderr in bounded chunks; return exit code. No interactive shell handed to the caller.
4. **Per-exec micro-scoping (v1-lite):** each exec gets a transient mount view — `/workspace` read-only by default, write access only to paths granted for that exec (full policy-driven version lands in P4).
5. **TTL reaper:** goroutine kills expired/idle sessions; on daemon restart, reconcile + reap orphaned sandboxes.
6. **State machine:** `creating → ready → (execing) → ended`; persisted enough to reap after restart.

## Tools & libraries
Go, Podman bindings, gVisor/runsc, `context` for cancellation, bounded `io` streaming.

## Acceptance criteria
- [ ] `POST /sessions` then `exec kubectl version --client` streams output + exit 0, < 5s cold.
- [ ] All hard-spec flags verified present on the running container (inspection test).
- [ ] Rootfs write outside `/workspace` fails; toolchain layer is read-only.
- [ ] `docker ps` fails; root escalation blocked; `/proc/<other-pid>` unreadable; ptrace denied.
- [ ] `uname -r` shows gVisor kernel.
- [ ] TTL expiry reaps the session; daemon restart reaps orphans.
- [ ] Exec output is bounded/streamed (no unbounded memory); truncation marker on cap.

## QA checklist
- [ ] Independently inspect the container spec for every hard-spec flag.
- [ ] Run the F1.5 escape probes against a live session.
- [ ] Force a docker-in-docker case → legible failure or documented tmpfs workaround, not a silent hang.
- [ ] No leaked sandboxes after destroy or reaper.
- [ ] Failure legibility: sandbox vs runtime vs (later) policy errors are distinguishable.

## Security considerations
- This is the core containment feature. Assert hardening in code; never rely on Podman/gVisor defaults.
- Assume the sandbox occupant is hostile: all exec inputs validated at the boundary.
