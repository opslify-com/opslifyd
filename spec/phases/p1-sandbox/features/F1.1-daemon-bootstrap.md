# F1.1 — Daemon bootstrap & REST API

**Phase:** P1 · **Status:** todo · **Owner:** Builder (Go) · **Depends on:** P0 · **Blocks:** F1.2

## Goal
The `opslifyd` daemon starts, loads config, exposes a REST API over a permissioned Unix socket, runs as the `opslify` user, and verifies its signed toolchain before doing anything.

## Implementation approach
1. `cmd/opslifyd` main: load `/etc/opslify/config.yaml`, structured logging (`slog`), graceful shutdown.
2. REST server over Unix socket `/run/opslify/opslifyd.sock` (perms 0660, group `opslify`). Router (`chi`/net-http). API versioned `/v1`.
3. Load daemon Ed25519 identity key (from F0.1). Fail fast if absent/mispermissioned.
4. On start: `EnvBuilder.Verify` the configured toolchain layer; refuse to serve if unsigned/mismatched.
5. Health endpoint; runtime capability probe (`GvisorRuntime.Available()`), surfaced in health.
6. systemd integration: sd-notify readiness, socket activation optional.

## Tools & libraries
Go, `chi` or stdlib `net/http`, `slog`, `crypto/ed25519`, systemd (`coreos/go-systemd`).

## Acceptance criteria
- [ ] Daemon starts as `opslify`, socket at correct path/perms/group.
- [ ] Refuses to start/serve if toolchain layer fails signature/digest verification.
- [ ] Refuses to start if identity key missing or perms != 0600.
- [ ] `GET /v1/health` returns runtime availability (gVisor present/absent).
- [ ] Clean shutdown on SIGTERM; no orphaned resources.

## QA checklist
- [ ] Socket not world-accessible; non-`opslify`-group user is denied.
- [ ] Tampered toolchain digest blocks startup with a legible message.
- [ ] Logs contain no secrets.

## Security considerations
- Socket is the entire trust boundary for local callers — perms are load-bearing.
- Verify-before-serve makes D1's signed toolchain non-optional.
