Secrets

the vault
A secret is a value you store once and never read back. Storing it gives you a reference — the name on the left. Everything downstream uses the reference: connections, policy, the agent's config. Nothing in opslify can turn a reference back into a value, which is why the reference is safe to write in a config file, paste in a ticket, or hand to an agent.

What happens next
You will not see this value again. It is sealed into the vault under your master key. No API, UI or socket route can return it — not to you, and not to an agent.
Value is encrypted and stored; you get the reference hcloud-token
You attach it to a connection — which decides how it is injected
The agent calls api.hetzner.cloud normally and the daemon adds the header at the boundary
Every use is recorded as cred.resolve — by reference, never by value
Or from the shell
# value from stdin — never an argument, # so it stays out of shell history $ opslify secrets add hcloud-token \ --provider hetzner paste value, then Ctrl-D $ opslify secrets ls REF PROVIDER USED BY LAST USED hcloud-token hetzner 0 never
Secret vs connection

A secret is the value. A connection is how it reaches an upstream — a header, a kubeconfig, an agent socket. One secret can back several connections: ssh-ops-fleet backs both the web fleet and db-01, each with its own destination constraint.

That split is why rotating a key is one action here rather than an edit in six config files.
