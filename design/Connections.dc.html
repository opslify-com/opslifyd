How SSH stays blind

The private key never enters the sandbox. The daemon runs the agent and forwards only the socket — the SSH agent protocol returns signatures, never key material.

Agent runs ssh web-01 in the sandbox
Handshake needs a signature → request crosses the forwarded socket
Daemon checks the destination is allowed, signs, records ssh.sign
Session opens. The key stayed on the host.
How kubeconfig stays blind

The sandbox gets a generated kubeconfig whose server: is the session proxy and whose user block is empty. kubectl works normally; the real token is added at the boundary.

Reading the file gets you a proxy address — useless off this host.
