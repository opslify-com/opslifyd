Which agent drives this project?

opslify does not ship a model. Any agent that speaks MCP can drive the sandbox — and it inherits this project's tools, skills, connections and policy either way. Set per project, so prod can run a model you trust while a scratch project runs a cheap local one.

Custom CLI any model
Point opslify at any command that speaks MCP over stdio — Gemini CLI, aider, opencode, or something you wrote. Configure it in the shell on the right.
<your command> --mcp opslifyd
configure

Whichever you pick, the sandbox boundary does not move. A local Qwen and a hosted Claude get the same five MCP tools, the same policy gates and the same audit trail — the model choice changes cost, latency and where your prompts go, never what the agent is allowed to do.

Where prompts go

Claude Code sends your prompts and command output to Anthropic. Qwen local keeps everything on this machine. Either way the daemon still redacts secrets before anything is recorded — but for regulated environments the local option is the one that keeps command output entirely on your hardware.

The configured agent is shown in the cockpit header at all times, and is recorded in every change's trace, so you always know which model made a decision.
